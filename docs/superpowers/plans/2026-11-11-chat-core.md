# Chat core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tin nhắn 1-1 (có hộp chờ) và nhóm theo team, realtime qua Pusher, ảnh private, đã xem, đang gõ, sửa/thu hồi, web push, trang `/messages`.

**Architecture:** Bảng mới trong schema `community`; `services/chat.service.js` giữ mọi luật nghiệp vụ trong transaction; sau commit, `services/chatRealtime.service.js` fan-out lên kênh `private-user-{publicId}` có sẵn (tin > 8 KB chỉ gửi ping) và gửi event Inngest cho push. Đọc qua route `GET` + React Query, ghi qua server action `runAction`. Ảnh đi qua adapter `lib/chatMedia.js` (MinIO local, Upstash Blob production) và route redirect có kiểm tra thành viên.

**Tech Stack:** Next.js 16 App Router, PostgreSQL (`lib/db.js`, `lib/dbTransaction.js`), Pusher + Beams, Inngest, TanStack Query 5, Zustand, zod, Vitest, `@aws-sdk/s3-request-presigner`, `@upstash/blob` (mới).

**Spec:** `docs/superpowers/specs/2026-11-11-chat-core-design.md`

## Global Constraints

- Public id: `cnv_` (conversation), `msg_` (message), `att_` (attachment) + `ulid().toLowerCase()`; regex `/^(cnv|msg|att)_[0-9a-z]{26}$/` theo từng loại. User id ra ngoài là `identity.users.public_id`.
- Thứ tự tin: `seq` = `chat_message.id` (bigint) trả ra dạng string; cursor tin `before=<seq>`; ✓✓ so `seq <= lastReadSeq`.
- Giới hạn (một chỗ, `lib/chat/limits.js`): `MAX_BODY = 4000`, `MAX_ATTACHMENTS = 4`, `MAX_IMAGE_BYTES = 5_000_000`, `IMAGE_TYPES = ["image/jpeg","image/png","image/webp"]`, `EDIT_WINDOW_MS = 15 * 60 * 1000`, `MESSAGE_PAGE = 30`, `INBOX_PAGE = 20`, `INLINE_PAYLOAD_BYTES = 8000`, `TYPING_THROTTLE_MS = 3000`, `TYPING_SHOW_MS = 5000`, `READ_DEBOUNCE_MS = 1000`, `ORPHAN_MAX_AGE_MINUTES = 60`, `ORPHAN_BATCH = 500`, `PUSH_PREVIEW_CHARS = 80`.
- Limiter mới trong `lib/rateLimit.js`: `chatSend` 30/60s, `chatRead` 120/60s, `chatTyping` 30/60s, `chatUpload` 20/60s. Báo cáo dùng `feedback` có sẵn. Route `GET` dùng `api`.
- Copy giao diện và lỗi theo ngôn ngữ app hiện tại (tiếng Anh). Chuỗi cố định: `"You can't send messages in this conversation"` (403 gửi), `"This message was unsent"`, `"[code]"`, `"[image]"`, `"N new messages"`, `"wants to message you"`.
- 404 cho mọi trường hợp "không phải thành viên / đã rời / không tồn tại / người nhận ẩn profile". 403 không nói lý do chặn.
- `UPSTASH_BLOB_TOKEN` chỉ dùng ở server; không có biến `NEXT_PUBLIC_` nào cho chat.
- Lỗi sau commit (Pusher, xoá file, Inngest send) chỉ log, không làm hỏng kết quả action.
- Test integration theo mẫu `__tests__/blog/blogReports.integration.test.js`: `describe.skipIf(!process.env.DATABASE_URL)`, user tạm có prefix `TAG`, xoá trong `afterAll`.

## Review Focus

1. Body chỉ gồm khoảng trắng / xuống dòng và không có ảnh → 422, không tạo tin (test ở Task 8).
2. Tin chứa HTML thô, `<script>`, ảnh hoặc link markdown → hiện như chữ, không sinh thẻ `img`/`a` markdown/`script` (test ở Task 13).
3. Người nhận 1-1 bị khoá tài khoản (`status <> 'active'`) sau khi hội thoại đã có → gửi tiếp trả 403, lịch sử vẫn đọc được (test ở Task 3).
4. `attachmentIds` của hội thoại khác, của người khác, hoặc đã gắn vào tin trước → 422, không gắn (test ở Task 5).
5. Event `chat-message` tới khi trang tin chưa nằm trong cache, hoặc tới hai lần, hoặc tới trước khi action optimistic trả về → không lỗi, không trùng, tin optimistic được thay bằng tin thật theo `clientId` (test ở Task 11).

    - `ConversationItem = { id, kind, title, image, state, lastMessage: { seq, preview, senderId, createdAt } | null, lastMessageAt, unread }`

FOR UPDATE`), kiểm tra block hai chiều, trạng thái người nhận, giới hạn 1 tin khi người nhận `pending`, chèn tin `ON CONFLICT (sender_id, client_id) DO NOTHING RETURNING`, cập nhật `last_message_*` và `last_read_message_id` người gửi.
